X Native Extension

What this extension actually does

Paste

On Ctrl+V (and the Mac Command+V equivalent) inside a composer, the extension cancels the paste and inserts text/plain with document.execCommand("insertText"). Image and file pastes are left alone. The composer is recognized by X's composer test ids (tweetTextarea_*, message composer) or by an accessible name such as “Post text” or “Reply”. The search box is not a composer.

This is not invisible typing. The text arrives in one editing command, including newlines and emoji, rather than as one keystroke per character. Extension-created events that the extension dispatches itself are untrusted, and this extension does not dispatch fake InputEvents. Sites can still look at timing, text length, focus, and their own editor model.

Event sequence measured on Chrome 156 and Chrome for Testing 157

For a rewritten paste of two lines, the page's own listeners saw:

  • no paste event
  • no beforeinput event
  • a trusted input event, inputType insertText, data set to the first line
  • a trusted input event, inputType insertText, data null, for the line break
  • a trusted input event, inputType insertText, data set to the next line

document.execCommand("undo") then emitted one trusted input with inputType historyUndo and restored the previous text. ClipboardEvent did not expose shiftKey. Holding Alt with Ctrl+V did not paste at all on Linux Chrome, so Alt is not the escape hatch.

An editor that updates only from beforeinput will not see this insertion in its model, even if the DOM changes. An editor that reads the DOM on input will. Live x.com was not signed in during automated tests, so the shipped composer was not confirmed.

Escape hatches

  • Turn the checkbox off.
  • Hold Shift while pasting (Ctrl+Shift+V or Shift+Insert).
  • Press the “next paste is normal” shortcut (default Alt+Shift+V), then paste once, including from the browser's Paste menu.

Pastes longer than 100,000 characters are not rewritten. Nothing is auto-posted.

Download full image

The menu uses the photo under the pointer, or every photo that belongs to that post when the pointer is not on one. Quoted posts are separate: a click inside a quote does not download the outer post's pictures. Profile pictures and video posters are skipped. The extension requests the same pbs.twimg.com/media URL already in the page, with the public name parameter set to orig, then large, then the in-page URL. It checks the file bytes and will not save an HTML error page as a picture.

Download full video

The extension only downloads https://video.twimg.com addresses that are already on the video element or that the page actually requested (resource timing while that video is playing). It does not build a video URL from an id, call X's private API, or read cookies in JavaScript. Fetches are performed by the extension to that host, with the browser's normal cookie jar, and are refused if the response redirects elsewhere.

  • A direct MP4 or WebM is saved as that format after the bytes are checked.
  • An unencrypted HLS playlist is fetched, the highest listed variant is chosen, and segments are joined. MPEG-TS is saved as .ts, not renamed to .mp4. An init segment plus fragmented MP4 is saved as .mp4 only if the joined bytes look like MP4.
  • Encrypted playlists are refused.
  • A separate audio rendition is not muxed. The toast says the file may be silent.
  • A blob: or MediaSource player with no real file URL is refused. The buffer is not saved, because it is often only a fragment. Play the video and try again.

Open and post

Open image in a new tab uses the full-size photo address. Open video uses a progressive MP4 or WebM the page already named. A blob address or a segmented stream is refused, and the post URL is not substituted. Post image and Post video fetch that file and place it on the composer’s file picker for review. They never click Post. The change event is untrusted, and a signed-in X composer was not tested. If a draft is already on the page, it is left alone and a new composer tab is opened. More than four images, a file over 32 MB, or a video that is not MP4 or WebM is refused instead of opening an empty composer.

Right-click

X replaces the browser menu with its own. A normal right-click on a post shows this extension’s actions on the page instead. A photo shows the image actions, a video or its poster shows the video actions, and text shows Screenshot post. Shift+right-click keeps X’s menu. Alt+right-click opens the browser menu, including Save image and this extension’s items.

Screenshot post

The browser captures the visible window as PNG (captureVisibleTab). The extension scrolls the selected post, crops to its box, stitches the slices, and restores the scroll position. Fixed and sticky bars that are not part of the post are hidden while capturing so they are not painted on top of it. Very tall posts are cut off with a message. The image shows the post as rendered, including the current video frame, not a downloaded video file. Expand “Show more” yourself if you want the hidden text in the picture.

A click on the on-page button does not grant activeTab. Press Alt+Shift+S, or choose Screenshot post from the browser menu (Alt+right-click). That invocation allows later on-page screenshots until the tab navigates. The extension does not request access to every website to get around this.

Permissions

PermissionWhy
storageRemember the paste rewrite checkbox on this browser.
contextMenusRegister the post actions. The menu you see is drawn on the page, because X hides the browser menu.
downloadsSave the image, video, or PNG into the X-Native folder in your downloads.
activeTabChrome refuses captureVisibleTab without this or access to every site. It applies only to the tab where you invoked the extension, such as the context-menu click.
https://x.com/* and https://twitter.com/*Run on X. These host permissions alone do not allow a screenshot.
https://pbs.twimg.com/*Download the post photo the page already referenced.
https://video.twimg.com/*Download a video file or HLS playlist the page already requested.

No tabs history permission, no <all_urls>, no clipboard permission, no remote code, and no analytics server.
